## 个人概述

围绕 CloudOps 场景从零搭建 Agent Runtime，覆盖可解释的 ReAct 执行、受治理的工具调用、上下文与 Token 预算、可恢复任务执行，以及从反馈数据到 Skill Candidate 的受控学习生命周期。项目重点解决 AI 应用与后端工程共同面对的三个问题：推理成本可控、能力迭代可评测、服务运行可观测且可恢复。

## 项目经历

### Athena Agent - 面向 CloudOps 的可治理 Agent Runtime

`个人项目 | 2026.xx - 至今`

#### 当前可投版（不写未实测数字）

- 从零设计并实现基于有界 ReAct Tick 的 Agent Runtime，使用结构化决策、工具权限边界、任务 Checkpoint、Lease 和幂等 Effect Journal 管理执行过程，使任务链路可解释、可恢复、可审计。
- 构建上下文治理能力：对 Evidence 做压缩与脱敏，控制输入 / 输出 Token 预算并在超预算时有序降级；接入可替换 TokenMeter 与复杂度感知模型路由，记录单任务上下文压力和成本相关数据。
- 实现受治理的自进化数据闭环：已验证轨迹与人工反馈生成 Skill Candidate，依次经过 Replay、Shadow、人工审核和 Handoff；候选策略不允许自动激活，避免未经验证的策略直接影响外部系统。
- 构建服务端运行边界，提供任务 API、持久化 Repository、Trace 透传、指标、限流、重试、熔断及 CloudOps 告警诊断与受控处置流程，覆盖 Agent 服务的可靠性与治理需求。
- 严格区分本地确定性 / mock 演示与真实 Provider 实验；真实模型账单、真实 Redis/PostgreSQL、真实集群和真实压测结果均需要在对应环境中复现后才进入简历。

#### 预期增强版（完成验收后替换到正式简历）

- **Token 成本与上下文效率优化【目标】**：通过 Evidence 摘要、分层记忆、检索去重、响应缓存和复杂度感知模型路由，优化成功任务的 Token 用量。在固定任务集、固定模型与固定质量阈值下，目标将 `total_tokens / successful_task` 降低 30%-50%，单成功任务模型成本降低 20%-40%，端到端 P95 延迟降低 20%-35%，且质量不发生实质回归。
- **基于评测反馈的受控自进化【目标】**：建设“失败 / 反馈样本沉淀 -> 策略候选生成 -> 离线 Replay -> Shadow 观测 -> 人工审核 -> 版本发布 / 回滚”的闭环。在冻结留出集上，目标实现任务成功率提升 5-10 个百分点、回归集通过率不低于 95%，并保持未经审核策略自动激活次数为 0。
- **Agent 评测、可观测性与服务端工程化【目标】**：建立数据集回归门禁和覆盖 Task、Model、Tool、Persistence 边界的调用链追踪。目标实现 Trace 覆盖率不低于 95%、100% 策略发布经过离线评测、可重试故障恢复率不低于 90%，并将不含模型推理的 Runtime 控制面 P95 开销控制在 300 ms 以内；QPS、P99 与可用性只在完成真实工作负载基线后确定。

## 两个投递方向的标题调整

### AI Agent / 大模型应用方向

`自研可治理 Agent Runtime，围绕 Token 成本治理、评测反馈驱动的受控自进化和全链路可观测性，构建面向 CloudOps 场景的可解释、可评测 Agent 执行闭环。`

重点保留：ReAct、上下文工程、Token 优化、模型路由、工具调用、评测集、Replay / Shadow、反馈数据、Prompt / Strategy 版本化。

### 后端开发 / AI 平台方向

`设计可恢复的 Agent 任务执行平台，围绕状态机、Lease、Checkpoint、幂等副作用、持久化、异步任务、限流重试、Trace 与指标治理，支撑 AI 服务稳定运行与能力迭代。`

重点保留：FastAPI、SQLAlchemy、Redis / PostgreSQL、幂等、事务边界、异步任务、缓存、限流、熔断、可观测性、Docker / Kubernetes。

## 推荐用词与禁用用词

推荐：

- “基于评测与反馈数据的受控自优化闭环”
- “Candidate -> Replay -> Shadow -> 人工审核 -> 版本化 Handoff”
- “Token 治理与上下文效率优化”
- “Agent 评测、可观测性与服务端工程化”

在真实实验完成前禁止：

- “模型已自主训练”或“完全自动自我进化”
- 仅靠估算 Token 推导出的 Provider 级成本降幅
- 没有工作负载与原始报告的 QPS、P99、可用性、MTTR
- 将 mock CloudOps 演示描述为真实集群生产结果

## 面试一句话

我把项目聚焦在三个让 Agent 从 Demo 走向工程系统的问题：如何控制 Token 成本，如何让策略迭代可评测可回滚，以及如何让每次任务执行在后端服务边界内可追踪、可恢复、可治理。

## 后续落地顺序

1. 建立真实基线：固定任务集、模型 / Prompt / 价格快照、Provider 用量、质量门禁和原始实验产物。

4. 完成服务端验收：真实 Redis/PostgreSQL、故障注入、按工作负载压测、Trace / Dashboard 和发布证据。
5. 将所有【目标】替换为真实可复现数据，并输出 Agent 重点版与后端重点版正式简历。
